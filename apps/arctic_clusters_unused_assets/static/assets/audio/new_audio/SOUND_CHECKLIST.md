## How to regenerate the audio sprite

After adding or replacing `.wav` files in this folder, run:

```bash
cd /workspaces/web-sdk/apps/arctic_clusters/static/assets/audio/new_audio

audiosprite -o ../sounds -f howler --export ogg,mp3,m4a,ac3 \
  bgm_main.wav \
  bgm_freespin.wav \
  bgm_winlevel_big.wav \
  bgm_winlevel_epic.wav \
  bgm_winlevel_max.wav \
  bgm_winlevel_mega.wav \
  bgm_winlevel_superwin.wav \
  jng_intro_fs.wav \
  sfx_btn_general.wav \
  sfx_btn_spin.wav \
  sfx_anticipation.wav \
  sfx_anticipation_start.wav \
  sfx_reel_stop_1.wav \
  sfx_reel_stop_2.wav \
  sfx_reel_stop_3.wav \
  sfx_reel_stop_4.wav \
  sfx_reel_stop_5.wav \
  sfx_royals_landing.wav \
  sfx_symbols_landing.wav \
  sfx_wild_explode.wav \
  sfx_scatter_reveal.wav \
  sfx_scatter_stop_1.wav \
  sfx_scatter_stop_2.wav \
  sfx_scatter_stop_3.wav \
  sfx_scatter_stop_4.wav \
  sfx_scatter_stop_5.wav \
  sfx_scatter_win.wav \
  sfx_scatter_win_v2.wav \
  sfx_multiplier_combine_a.wav \
  sfx_multiplier_combine_b.wav \
  sfx_multiplier_explosion_a.wav \
  sfx_multiplier_explosion_b.wav \
  sfx_multiplier_explosion_c.wav \
  sfx_multiplier_landing.wav \
  sfx_multiplier_reset.wav \
  sfx_multiplier_up.wav \
  sfx_multiplier_update.wav \
  sfx_multiplier_win.wav \
  sfx_bigwin_coinloop.wav \
  sfx_winlevel_end.wav \
  sfx_winlevel_nice.wav \
  sfx_winlevel_small.wav \
  sfx_winlevel_standard.wav \
  sfx_winlevel_substantial.wav \
  sfx_youwon_panel.wav \
  sfx_fs_respins.wav \
  sfx_superfreespin.wav \
  tumble_win_1.wav \
  tumble_win_2.wav \
  tumble_win_3.wav \
  tumble_win_4.wav
```

This overwrites `../sounds.json`, `../sounds.mp3`, `../sounds.ogg`, `../sounds.m4a`, `../sounds.ac3`.

Then **immediately** run the fix script to convert `audiosprite`'s output to the correct Howler format:

```bash
node fix_sounds_json.mjs
```

This fixes three things the raw `audiosprite` output gets wrong:
1. Renames `"urls"` → `"src"` (Howler uses `src`, not `urls`)
2. Corrects paths from `"../sounds.ogg"` → `"./assets/audio/sounds.ogg"`
3. Adds `true` loop flags to BGM/loop sprite entries
4. Adds the `"config"` volume block

No other code changes needed after regeneration — the sprite names stay the same.
